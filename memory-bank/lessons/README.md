# Implementation Lessons

This directory contains concise, student-facing lessons drawn from verified implementations. The agent explains every implementation in its completion response, but saves a lesson here only when the learning is reusable beyond that response.

## Naming and numbering

- Name lesson files `NN-<project_name>.md`, starting at `01` and using the next unused zero-padded number: for example, `01-brasaland.md`.
- Use a concise kebab-case project name. Do not renumber existing lessons.
- Before creating a new lesson, ask the user for the project name if they have not provided one. If a matching lesson already exists, update it rather than creating a duplicate.
- Keep this index in sync when lessons are added, renamed, or removed.

## Lesson contents

Each lesson should cover:

- The problem or goal and relevant project context.
- Why the implementation approach was chosen.
- How the implementation works, with small examples taken from the actual changed code and a plain-language explanation of each example.
- Relevant file links, validation performed, and any important limitations or follow-up work.

Do not copy whole files, claim unverified behavior, or duplicate stable rules and company facts. Update an existing lesson when it is the best fit; create a new numbered lesson only for a distinct, reusable topic.
